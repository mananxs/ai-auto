# TalentGraph

AI-assisted developer sourcing. A recruiter opens a job, the app finds matching GitHub developers
using **public profile metadata only** (bio, location, account age, languages, repository topics),
and Gemini scores each candidate against the job. It never reads code, commits, or file contents.

Single Next.js app. No Python, no separate backend, no Redis.

> Status: **Phase 1 (project + database)** is complete. Later phases add the GitHub client,
> Gemini matcher, background worker, and dashboard. This README grows with them.

## Run it in GitHub Codespaces

### 1. Get three free credentials

| What | Where |
| --- | --- |
| Neon Postgres | https://neon.tech -> create a project. In **Connect**, copy the connection string twice: once with **Connection pooling ON** (host contains `-pooler`) and once with it **OFF**. |
| GitHub token | https://github.com/settings/tokens -> *Tokens (classic)* -> generate with **no scopes ticked**. |
| Gemini key | https://aistudio.google.com/apikey |

### 2. Install and configure

In the Codespaces terminal:

```bash
npm install
cp .env.example .env
openssl rand -base64 32      # copy the output into TOKEN_ENCRYPTION_KEY in .env
```

Edit `.env` and fill in `DATABASE_URL`, `DIRECT_URL`, `TOKEN_ENCRYPTION_KEY`, `GEMINI_API_KEY`, `GITHUB_PAT`.

### 3. Create the database tables and seed data

```bash
npx prisma migrate dev       # applies prisma/migrations (enables pgvector, tables, CHECK, HNSW indexes)
npx prisma db seed           # creates org, recruiter, encrypted GitHub token, sample job; prints the job ID
```

If `migrate dev` complains about the shadow database or extension permissions, use
`npx prisma migrate deploy` instead. It applies the same SQL without a shadow database.

### 4. Start the app

```bash
npm run dev
```

Phase 4 adds a second terminal for the worker: `npm run worker`.

Open port 3000: Codespaces shows a notification, or open the **Ports** tab, find port **3000**,
and click the globe icon (Open in Browser). Keep the port private; only you need it.

### 5. Verify Phase 1

Open `<forwarded-url>/api/health`. You should see:

```json
{ "ok": true, "database": "connected", "pgvectorVersion": "0.8.0", "seeded": { "jobs": 1, "recruiters": 1 } }
```

(The pgvector version number depends on Neon.)

## Database notes

- `DATABASE_URL` is the **pooled** Neon host (`-pooler`, with `pgbouncer=true`). The app uses it at runtime.
- `DIRECT_URL` is the **direct** host. Prisma uses it for migrations (`migrate dev/deploy`),
  because migrations need session-level features that the pooler does not support.
- Tables are snake_case (`match_scores`), columns are camelCase. In raw SQL, quote columns: `m."jobId"`.
- Ids are generated by Postgres (`gen_random_uuid()`), so raw `INSERT ... ON CONFLICT` works.
- Raw SQL `UPDATE`s must set `"updatedAt" = now()` themselves (Prisma only does it for client writes).
- GitHub and OAuth tokens are stored as `v1:<iv>:<tag>:<ciphertext>` using AES-256-GCM.
  Losing or changing `TOKEN_ENCRYPTION_KEY` makes stored tokens unreadable. Re-run the seed to store a fresh one.

## Troubleshooting

**`Can't reach database server` / SSL errors**
- Both URLs must end with `sslmode=require`.
- Neon computes sleep when idle; the first connection can take a few seconds. Retry, and keep `connect_timeout=15`.
- Check you did not paste the password with special characters unescaped (URL-encode `@`, `:`, `/`).

**`prepared statement "s0" already exists` / random pooler errors**
- `DATABASE_URL` points at the pooler but is missing `pgbouncer=true`. Add `&pgbouncer=true`.

**`migrate` hangs or says a lock timed out**
- `DIRECT_URL` is wrong or accidentally uses the `-pooler` host. Migrations must use the direct host.

**`permission denied to create extension "vector"` or shadow database errors**
- Use `npx prisma migrate deploy`, or run `CREATE EXTENSION IF NOT EXISTS vector;` once in the Neon SQL editor and retry.

**`TOKEN_ENCRYPTION_KEY must decode to 32 bytes`**
- Generate it with `openssl rand -base64 32` (not hex, not a passphrase).

**`GITHUB_PAT is missing` when seeding**
- Add `GITHUB_PAT` to `.env` and re-run `npx prisma db seed`.
